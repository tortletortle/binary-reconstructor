# V0.17 — Ghidra structured P-code bridge

## Goal

Replace the previous raw-C-only Ghidra adapter with a structured export contract that captures the decompiler C listing, function metadata, HighFunction P-code operations, and basic-block CFG edges. The Python side validates that contract, classifies control flow and unsupported operations, and lowers a deliberately narrow P-code subset into the existing uint32 expression verifier.

## Implemented

1. `ChronoExport.java` now exports `function.json` alongside `decompiled.c` and `entry.txt`.
2. The JSON includes Ghidra version, processor language ID, endianness, pointer size, function entry/signature/calling convention/return and parameter storage, including ABI register checks, P-code blocks, predecessor/successor IDs, and each P-code operation's opcode, mnemonic, sequence address, output, inputs, and varnode storage/high-variable metadata.
3. `ghidra_adapter.py` invokes `analyzeHeadless`, validates the JSON schema, checks function identity and entry consistency, enforces export-size limits, and hashes the original binary.
4. `ghidra_pcode.py` validates CFG edge consistency, detects cycles, inventories operations, and rejects unsupported data flow.
5. `lower_linear_uint32` lowers a narrow one-basic-block x86-64 SysV function with one 32-bit parameter and 32-bit return. Supported operations are `COPY`, `INT_ADD`, `INT_SUB`, `INT_MULT`, `INT_XOR`, `INT_AND`, `INT_OR`, `INT_LEFT`, `INT_RIGHT`, `INT_2COMP`, `INT_NEGATE`, `INT_ZEXT`, and `RETURN`.
6. `ghidra_pipeline.py` compiles the generated candidate, asks the existing bit-vector verifier to compare the original named function with the candidate, and replays 24 boundary probes plus a deterministic pseudorandom sample. A candidate is marked `DIRECT_VERIFIED` only when SMT returns `UNSAT` and every native replay agrees.

## Ghidra API/launcher contract

The exporter uses Ghidra's documented Headless Analyzer `-postScript <ScriptName> [<arg>]*` interface and reads script arguments with `getScriptArgs()`. It uses `DecompileResults.getHighFunction()`, `HighFunction.getBasicBlocks()`, `PcodeBlockBasic.getIterator()`, and `PcodeOp`/`Varnode` metadata to build the JSON document.

## Deliberate limits

- This is not a general P-code interpreter or general decompiler.
- Multi-block CFGs, branches, loops, calls, indirect flow, memory operations, signed extension, pointer arithmetic, and unknown operations are rejected by the current lowering path.
- The current formal backend models Linux x86-64 SysV and maps the first parameter through `RDI`/`EDI`; other ABIs are rejected.
- Native replay currently requires a loadable ELF shared object and a dynamically exported target function symbol. Arbitrary firmware images and non-loadable executables are not yet accepted by this pipeline.
- The Ghidra adapter can export on supported Ghidra platforms, but the current ChronoCompiler formal pipeline requires Linux x86-64, GCC-compatible compilation, GNU `objdump`, and the system Z3 library.
- Native compilation and `ctypes` execution are not sandboxed. Use trusted binaries only.

## Validation evidence

- Full regression suite: 119/119 passed.
- Structured-export contract tests use a mocked Headless Analyzer launcher and synthetic schema-v1 P-code JSON.
- P-code lowering tests use a real locally compiled `mul_add(uint32_t)` shared object, then run the generated candidate through the existing SMT model and native replay.
- The positive fixture (`x * 5 + 3`) returned SMT `UNSAT` and passed 4,120 native inputs (24 boundary values plus 4,096 deterministic pseudorandom inputs).
- The deliberately wrong fixture (`x * 5 + 4`) returned SMT `SAT`; the concrete counterexample was replayed against the original native function and candidate.
- Cycle, wrong-function, inconsistent-edge, memory, unsupported-op, and non-SysV argument-register cases fail closed.

**Important:** no Ghidra installation is present in the development container. The Java script has not yet been compiled or run inside Ghidra, and no real Ghidra-generated P-code export has been validated. The structured JSON fixture is synthetic and is only a contract test. Therefore V0.17 is a tested P-code frontend prototype, not a completed real-Ghidra end-to-end integration.

## Reproduction

```sh
python -m unittest discover -v
python ghidra_pipeline.py /path/to/trusted.so function_name --trusted
```

Set `GHIDRA_HEADLESS` to the path of `support/analyzeHeadless` (Linux) or `support/analyzeHeadless.bat` (Windows), or set `GHIDRA_INSTALL_DIR` to the Ghidra installation directory.

For Ghidra 12.2, the [official Getting Started guide](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.2_build/GhidraDocs/GettingStarted.md) lists Java 25 64-bit JDK as the minimum software requirement. Confirm the installed Ghidra release's own Java requirement before launching Headless Analyzer.
