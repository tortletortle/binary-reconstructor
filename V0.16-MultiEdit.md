# V0.16 — Bounded multi-edit branch repair

## Objective

V0.15 repaired a single comparison operator or literal in one branch predicate. V0.16 extends the same counterexample-guided search to at most two atomic edits, allowing either two different branch predicates to be repaired or two separate sites inside one predicate to be changed together.

## Search strategy

1. Verify the original reconstructed candidate. Only a replayed SAT counterexample can seed repair.
2. Build one-edit proposals for every conditional branch. Rank proposals by how many accumulated counterexamples they already satisfy, then by a simple literal-distance heuristic.
3. Try one-edit candidates first.
4. If no single edit proves equivalent, combine ranked proposals across different branches first.
5. Then combine two different mutation sites inside the same branch predicate.
6. Every combined candidate is lowered again and screened against all accumulated counterexamples before compilation.
7. A new SAT counterexample restarts the search with a stronger example set. Only SMT UNSAT is accepted as REPAIRED_VERIFIED.

The current search allows at most two edits. It is a bounded heuristic search, not complete synthesis. The literal candidate set remains common boundaries plus the current literal and counterexample input ±1/±2. Per-branch option count, candidate count, compiled candidate count, path count, wall time, and SMT timeout are configurable.

## Development pilot

The pilot contains two positive repair scenarios and one three-error negative control. Each was compiled with GCC 14.2 and Clang 17 at -O2, producing six trusted shared-object fixtures.

| Scenario | GCC | Clang |
|---|---|---|
| Two independent branch thresholds corrupted | REPAIRED_VERIFIED | REPAIRED_VERIFIED |
| Two edits needed in one predicate (operator + threshold) | REPAIRED_VERIFIED | REPAIRED_VERIFIED |
| Three independent branch errors with max_edits=2 | UNRESOLVED | UNRESOLVED |

Aggregate results:

| Metric | Result |
|---|---:|
| Fixtures | 6 |
| Positive cases repaired and SMT-verified | 4/4 |
| Three-edit negative controls correctly unresolved | 2/2 |
| Candidate combinations generated | 3,953 |
| Single-edit candidates | 593 |
| Multi-edit candidates | 3,360 |
| Counterexample-pruned candidates | 3,930 |
| Candidate SMT checks | 23 |
| CEGIS restarts | 19 |
| Cross-compiler comparisons | 16,452 |
| Cross-compiler mismatches | 0 |
| Full regression tests | 98/98 |

Cross-compiler replay uses 17 fixed boundary probes and 4,096 seeded pseudorandom uint32 inputs for each of four accepted candidates (4,113 × 4 = 16,452). It is supplemental differential testing, not a formal proof. Mean repair runtime across the six fixtures was about 0.473 seconds (median 0.419 s, maximum 0.664 s), excluding cross-compiler replay.

The negative control is important: three independent threshold errors were not silently accepted under a two-edit budget. The search exhausted its configured candidate budget and returned UNRESOLVED. This does not prove that every three-error input will be rejected; it demonstrates the behavior on this fixture.

All pseudocode was manually authored. No real Ghidra output or firmware corpus was used. These results demonstrate the bounded algorithm on small controlled cases only.

## Scope and safety

- Trusted pure uint32 -> uint32 functions under the current x86-64 SysV machine model.
- Acyclic forward CFG only. Loops, memory, pointers, side effects, external calls, arbitrary C and unsupported instructions remain out of scope.
- At most two atomic edits; no arbitrary multi-edit synthesis.
- Only branch comparison operators and integer literals are mutated. Arithmetic/data-layout repair is not included.
- Native compilation and execution are not sandboxed. Use trusted fixtures only.
- SMT UNSAT is relative to the supported machine-code model, not all x86 semantics.
