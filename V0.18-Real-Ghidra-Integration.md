## API correction found before runtime testing

Inspection of the official Ghidra_12.2_build source showed that Language.getRegister accepts:

    getRegister(AddressSpace addrspc, long offset, int size)

The V0.17 exporter had called it with (Address, int), which is not the Ghidra 12.2 API signature. The exporter now passes the varnode's address space, offset, and size.

## Important P-code semantic correction

The first real export showed that every operation returned by the HighFunction basic-block iterator had PcodeOpAST.isDead() == true, including INT_MULT, INT_ADD, COPY, and RETURN.

That API flag is internal AST bookkeeping and is not a semantic dead-code indicator for operations enumerated from the basic-block list. V0.17 incorrectly serialized it as a dead-code flag and the Python lowerer consequently skipped the entire function body.

V0.18 schema v2 now records the value as ast_dead_flag. The lowerer consumes operations enumerated by each PcodeBlockBasic and does not use that internal flag as a liveness filter. Schema v1 remains readable for backwards compatibility.

## New real-integration workflow

The .github/workflows/ghidra-12-2-integration.yml workflow:

1. Uses Java 25 and Python 3.13.
2. Downloads the official Ghidra 12.2 release archive.
3. Verifies the archive SHA-256 against the release asset digest before extraction.
4. Runs the complete Python regression suite.
5. Builds a tiny x86-64 ELF shared-library fixture with DWARF parameter metadata and deliberately constrained machine code.
6. Runs analyzeHeadless with ChronoExport.java.
7. Validates the actual JSON export and lowers the actual P-code.
8. Compiles the candidate, checks equivalence with the existing bit-vector model, and replays boundary plus deterministic random inputs.
9. Uploads the raw P-code export, decompiler C output, smoke report, and fixture binary even when the integration job fails.

## Controlled native fixture and real result

The tests/fixtures/ghidra_mul_add.c fixture uses a DWARF-described uint32_t function and inline assembly to keep its body to:

- imul $5, %edi, %eax
- add $3, %eax
- ret

Actual Ghidra 12.2 output:
- Program language: x86:LE:64:default
- Function: chrono_mul_add
- P-code blocks: 1
- CFG edges: 0
- P-code operations: INT_MULT, INT_ADD, COPY, RETURN
- Lowered expression: ((x * 5u) + 3u)
- Formal result: SMT UNSAT
- Native replay: 4,120 inputs passed
- Final smoke status: DIRECT_VERIFIED

The parameter and return ABI are checked from variable storage (EDI/RDI and EAX/RAX), not inferred solely from the decompiler's calling-convention display string.

## Cross-toolchain correction

The Ubuntu 26.04 runner's GCC 15.2.0 emitted BMI2 RORX for one generated byte-swap candidate. The formal verifier did not previously model that instruction. V0.18 adds immediate-count RORX semantics, with positive and negative equivalence tests. The typed-bridge test target was also changed to deterministic register-only assembly so it does not accidentally depend on GCC's stack-spill decisions.

This is a targeted instruction-model extension, not a claim that arbitrary BMI2 or memory instructions are supported.

## Deliberate limits

- This is not a general P-code interpreter or general decompiler.
- Current automatic P-code lowering supports one basic block, one 32-bit parameter, one 32-bit return, x86-64 SysV RDI/EDI argument and RAX/EAX return storage, and a small unsigned arithmetic subset.
- Multi-block branches, loops, memory operations, pointers, calls, indirect flow, signed extension, and unknown operations are rejected by the current lowering path.
- Native replay currently requires a loadable ELF shared object and a dynamically exported target function symbol.
- The current formal backend is Linux x86-64-specific.
- Native compilation and execution are not sandboxed. Only trusted binaries may be used.
