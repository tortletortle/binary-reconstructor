# V0.15 — Counterexample-guided branch predicate repair

## Objective

V0.14 could lower a bounded acyclic CFG into a path-expanded expression and prove or refute equivalence, but it could not repair a wrong branch predicate. V0.15 adds a bounded CEGIS loop over branch conditions.

## Search loop

1. Parse and lower the input pseudo-C function using the V0.14 CFG bridge.
2. Compare the compiled candidate against the original trusted binary with the existing machine-code SMT model.
3. Require a concrete SAT counterexample and native replay before starting repair. Unsupported, UNKNOWN, and model-mismatch results are not repair seeds.
4. Enumerate one atomic edit to one branch predicate: a comparison operator (`==`, `!=`, `<`, `<=`, `>`, `>=`) or an integer literal.
5. Build a new candidate CFG and evaluate it on every accumulated counterexample. Candidates that fail any example are pruned before compilation.
6. Run the existing compile + native counterexample replay + SMT equivalence verifier on remaining candidates.
7. A new SAT counterexample is added to the example set and the bounded search restarts. Only `UNSAT` returns `REPAIRED_VERIFIED`.

The literal neighborhood includes common integer boundaries, the current literal ±1/±2, and each counterexample input ±1/±2. It is a heuristic finite search, not complete synthesis. It does not currently derive the runtime value of an arbitrary local-variable expression to seed a replacement constant.

## Scope and safety

- One pure unsigned 32-bit input and one unsigned 32-bit return, x86-64 SysV machine model.
- Acyclic CFG only; no loops/backedges, memory, pointers, side effects, or external calls.
- One atomic edit per candidate; no simultaneous multi-branch edits.
- Branch comparison operator and literal edits only. It does not repair arithmetic expressions, data layout, calling conventions, or types.
- Search limits: candidates, SMT-checked builds, path count, wall-clock budget, and per-query solver timeout are configurable.
- Only trusted fixtures. Candidate compilation and native execution are not sandboxed. Do not use untrusted binaries.
- SMT `UNSAT` means equivalent within the current supported machine-code semantics model, not a proof that the model covers all x86 instructions or all program behavior.

## Development pilot

Seven manually authored branch-error patterns were compiled with GCC 14.2 and Clang 17 at `-O2`, producing 14 trusted shared-object fixtures. All 14 initial candidates returned replayable `COUNTEREXAMPLE`; all 14 were repaired and returned SMT `UNSAT`.

| Metric | Result |
|---|---:|
| Binary fixtures | 14 |
| Initially incorrect candidates | 14 |
| Repaired and formally verified | 14 |
| Candidate mutations generated | 123 |
| Candidates pruned by accumulated counterexamples | 91 |
| Candidate SMT checks | 32 |
| New counterexample restarts | 18 |
| Accumulated counterexample instances | 32 |
| Cross-compiler native comparisons | 57,652 |
| Cross-compiler mismatches | 0 |
| Full regression tests | 95/95 |

The cross-compiler replay uses 22 fixed boundary probes plus 4,096 seeded pseudorandom uint32 inputs for each of 14 accepted candidates (4,118 × 14 = 57,652). It is supplemental differential testing, not a formal proof. Mean repair runtime in the final single-edit run was about 0.191 seconds per fixture (median 0.184 s, maximum 0.319 s), excluding cross-compiler replay.

All benchmark pseudocode was manually authored; it was not emitted by a real Ghidra run. These are small development fixtures, not an independent blind corpus or a firmware benchmark. The results establish that the bounded branch-repair loop works on these cases only.

## Reproduction

```sh
python -m unittest discover -v
python experiment_branch_repair.py
python branch_repair.py /path/to/trusted.so --pseudocode proposal.c --trusted
```

Environment used for this run: Python 3.13.5, GCC 14.2.0, Clang 17.0.0, Linux x86-64, system `libz3.so.4`.

See `branch-repair-summary-v015.csv`, `branch-repair-results-v015.json`, and `regression-v015.txt` for the per-case data and test log.
